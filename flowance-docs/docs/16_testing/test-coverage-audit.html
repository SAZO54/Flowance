§1

前回指摘事項の解消状況

前回の検出事項 5 件はすべて解消を確認した。

✓
apps/settings のテスト 11 件が未実行だった問題

tests/__init__.py と tests/presentation/__init__.py が追加され、11 件が実行対象に復帰。 settings/application/service.py のカバレッジは 33% → 96%、 presentation/views.py は 48% → 100% に改善した。

✓
breakMinutes の境界が週次予定と個別予定で食い違っていた問題

実装・テスト・仕様書の三点が同時に更新されている。前回「仕様上どちらが正か決まっていない」と指摘した点が、 先に文書側で確定されてから実装が揃えられており、対処の順序として正しい。

generation.py:70 if break_minutes < 0 or break_minutes >= duration: # 週次 generation.py:85 if break_minutes < 0 or break_minutes >= duration: # 個別 docs/14_schedule-generation/schedule-generation-design.md L34 breakMinutes は 0 以上、予定時間より短い値でなければならない。 L35 breakMinutes が予定時間と同じ、または予定時間を超える場合は…無効とする。 L36 週次予定と個別予定で breakMinutes の境界仕様を揃える。
✓
Application 層のテストがゼロだった問題

settlements / schedules / files の 3 アプリに application テストが新設され、 16 件が追加された。settlements/application/service.py は Idempotency-Key の検証を含めて 92% → 94%、 files/tasks.py は 65% → 86% に改善している。

✓
pytest が実行不能／テストユーティリティ未使用だった問題

pytest.ini（domain / application / integration マーカー定義つき）、 ルート conftest.py、apps/common/tests/factories.py が追加され、 factory_boy が実際に使われるようになった。pytest -q で 107 件が通る。

✓

.github/workflows/ci.yml が新設され、Docker Compose で PostgreSQL / Redis を起動したうえで Ruff → Ruff format → mypy → Django check → migration check → テストを実行する構成になった。 AGENTS.md §13 のバックエンド項目をすべて満たしている。

§3

残存ギャップ

今回の調査で新たに確認した、まだ塞がっていない箇所。

重大

CI に flowance-web のジョブが存在しない

.github/workflows/ci.yml に定義されているジョブは flowance-api の 1 つだけで、 新設された 28 件の Web テストは CI で一度も実行されていない。 npm run lint、npm run typecheck、next build も同様である。

AGENTS.md §13 のフロントエンドチェック項目（TypeScript typecheck / ESLint / Next.js build / Vitest）が すべて CI 未実行の状態にあり、Phase1 受入条件「Next.js build と Docusaurus build が成功する」も検証されていない。 テストを整備した効果が、レビュー時点では得られない。

対処：ci.yml に flowance-web ジョブを追加する。 バックエンドと違い DB もサービスも不要なため、setup-node + npm ci で完結し、実行時間もごく短い。 コードは §4 に掲載。
高

flowance-web の src/domain/ 592 行にテストが 1 件もない

Web のテストは application/（5 ファイル）、shared/（2 ファイル）、 presentation/features/clients/（1 ファイル）に置かれている。 一方 src/domain/ の 14 ファイル（contract.ts 68行、settings.ts 76行、 schedule.ts 73行、workRecord.ts 72行、project.ts 62行、 dateTime.ts 52行ほか）は未着手のままである。

AGENTS.md §9 により、この層は React・Next.js・TanStack Query・React Hook Form・Zod・FullCalendar・ブラウザ API から 独立している。つまり jsdom すら不要で、最も安く速くテストできる層が最後まで残っている状態で、 優先順位が逆になっている。

高

Playwright / E2E が未導入

AGENTS.md §3.1・§13 が指定する Playwright は package.json に存在しない。 docs/16_testing/test-design.md の Phase1 受入条件は 「予定生成、稼働実績、月次精算の主要フローが通る」ことを求めているが、 現状これを通しで検証する手段がない。

単体テストが揃った今が導入の適期である。前回同様、対象は 登録 → ログイン → クライアント登録 → 案件登録 → 契約登録 → 予定生成 → 稼働実績 → 月次精算の 1 本に絞ってよい。

中

CI が pytest ではなく manage.py test を使っている

pytest.ini に domain / application / integration の マーカーが定義され、テストコード側でも pytestmark が使われているにもかかわらず、 CI の実行コマンドは python manage.py test --settings=config.settings.test である。

両方とも 107 件が通るため実害は出ていないが、マーカーが機能しないため 「Domain だけ 1 秒で回す」といった段階的実行ができない。 AGENTS.md §13「変更のリスクに見合った最小限の検証を実行する」を実践するうえで、この差は効いてくる。 あわせて pytest --cov でカバレッジを CI 出力に載せられる。

中

Web のカバレッジが計測されていない

@vitest/coverage-v8 が未インストールで、test:coverage スクリプトもない。 API 側は coverage で 91% と把握できているのに対し、Web 側は 28 件がどこを通っているのか分からない状態にある。 上記の src/domain/ 未着手も、計測していれば数値として即座に現れる。

低

Application テストが 3 アプリに留まる

settlements / schedules / files には application テストが追加されたが、 clients（services.py 83%）、projects（84%）、 work_records（89%）、contracts（90%）にはまだない。 いずれも権限分岐とテナント境界を持つため、優先度は高くないが将来的な対象になる。

§4

AGENTS.md に則った単体テストのすすめ

基盤は整ったため、今回は残存ギャップを塞ぐための具体案に絞る。 層の分け方や pytest 設定は前回提案どおり実装済みなので繰り返さない。

4.1 前提として守られている原則

AGENTS.md §6 Domain code must not depend on Django, DRF, ORM, ...

→ settlements/tests/domain/ などが DB なしで通ることで、依存方向が実際に守られていることが証明された。この性質は今後も回帰チェックとして機能する。

AGENTS.md §9 Keep domain concepts independent from React, Next.js, ... and browser APIs.

→ Web も environment: 'node' を既定にし、DOM が要るファイルだけ // @vitest-environment jsdom を宣言する構成になっており、原則が設定に反映されている。

AGENTS.md §14 Keep documents and implementation consistent when a change affects both.

→ breakMinutes の修正が仕様書・実装・テストの三点同時更新で行われた。今後の業務ルール変更もこの手順を踏襲する。

4.2 最優先：CI に flowance-web ジョブを追加する

既存の flowance-api ジョブと並列に置く。DB もサービスも不要なため、追加コストはほぼゼロ。

.github/workflows/ci.yml — flowance-api ジョブの後に追記
  flowance-web:
    name: flowance-web
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: flowance-web
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
          cache-dependency-path: flowance-web/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Lint
        run: npm run lint

      - name: Typecheck
        run: npm run typecheck

      - name: Unit tests
        run: npm run test

      # Phase1 受入条件「Next.js build が成功する」の検証
      - name: Build
        run: npm run build
あわせて API ジョブのテストコマンドを pytest に寄せる。 ci.yml の python manage.py test --settings=config.settings.test を pytest --cov=apps --cov-report=term-missing に置き換えると、 pytest.ini に定義済みのマーカーが活き、カバレッジもログに残る。 ローカルで pytest -m domain（DB なし・1 秒未満）だけを回す運用も可能になり、 AGENTS.md §13 の「変更のリスクに見合った最小限の検証」が実践できる。
